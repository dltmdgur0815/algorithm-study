# 알고리즘

수업 예제를 바탕으로 조건을 조금 바꾸거나 기능을 덧붙인 코드 모음.
코드 파일에는 함수만 두고, 추가한 부분은 여기에 정리했다.

## 02. 자료구조 - 따옴표 안의 괄호 구분

[01_bracket_checker.py](02-DataStructure/01_bracket_checker.py)

괄호를 전부 세면 `print("(")`도 오류로 나온다. 따옴표 안의 내용은 문자열이므로 괄호 검사에서 빼는 `check_code_brackets()`를 추가했다. 따옴표 종류를 저장하고, 역슬래시 다음 문자는 따옴표를 닫는 문자로 처리하지 않는다.

`check_code_brackets('print("(")')`의 결과는 `(True, None)`이다. 닫히지 않은 따옴표는 시작 위치를 반환한다. 한 줄짜리 작은따옴표·큰따옴표 문자열을 가정한 예제로, 주석이나 삼중 따옴표까지 해석하는 Python 문법 검사기는 아니다. 시간과 공간은 각각 O(n)이다.

## 03. 시간복잡도 - 중복된 값의 범위

[01_search_comparisons.py](03-Complexity/01_search_comparisons.py)

이진 검색은 같은 값이 여러 개 있으면 그중 한 위치만 찾는다. `find_range()`는 이진 검색을 두 번 해서 처음 위치와 마지막 위치를 찾는다. 같은 값을 찾은 뒤 양옆으로 하나씩 이동하는 방법은 중복이 많으면 O(n)이 될 수 있어서 사용하지 않았다.

`find_range([1, 2, 2, 2, 4], 2)`는 `(1, 3)`, 없는 값을 찾으면 `(-1, -1)`이다. 입력은 정렬되어 있어야 하고 위치는 0부터 센다. 시간 O(log n), 추가 공간 O(1)이다.

## 04. 정렬 - 높은 점수부터 정렬

[01_insertion_sort.py](04-Sorting/01_insertion_sort.py)

삽입 정렬에 `reverse`를 추가해서 내림차순도 가능하게 했다. 점수처럼 높은 값부터 봐야 하는 경우에 사용할 수 있다. 값이 같으면 옮기지 않아서 동점자의 원래 순서는 유지된다.

```python
students = [('A', 80), ('B', 90), ('C', 80)]
insertion_sort(students, key=lambda x: x[1], reverse=True)
```

결과는 `[('B', 90), ('A', 80), ('C', 80)]`이다. 방향만 바꾸므로 최선 O(n), 평균·최악 O(n²)은 같다. 원본을 복사하므로 공간은 O(n)이다.

## 05. 검색 트리 - 구간에 속한 번호 찾기

[01_bst.py](05-SearchTree/01_bst.py)

한 번호의 존재 여부를 찾는 것에서 범위를 검색하는 `range_search()`로 넓혔다. 작은 번호부터 확인하되, 현재 번호가 하한보다 작으면 왼쪽은 확인하지 않는다. 상한을 넘으면 검색을 멈춘다.

`[42, 18, 65, 9, 27, 53, 78]`을 넣은 트리에서 `range_search(root, 20, 60)`은 `[27, 42, 53]`이다. 양 끝 값도 포함한다. 균형 잡힌 트리에서는 높이 h와 결과 수 k에 대해 O(h + k)이고, 한쪽으로 치우친 트리는 최악 O(n)이다. 결과 외 스택 공간은 O(h)이다.

## 06. B-트리 - 범위 검색과 방문 노드

[01_btree_search.py](06-BTree/01_btree_search.py)

B-트리에도 `range_search()`를 추가했다. 키 사이의 범위를 이용해 필요한 자식만 내려가고, 어떤 노드를 방문했는지도 같이 반환한다.

`range_search(make_tree(), 25, 40)`의 결과는 `([28, 35], [[22, 41], [28, 35]])`이다. 25~40에 포함되는 키는 28과 35이고, 왼쪽·오른쪽 리프는 방문하지 않는다. 전체 범위를 찾으면 모든 키를 확인하므로 최악 O(n)이다. 방문 경로와 결과를 저장하는 공간도 최악 O(n)이다. 트리는 미리 구성하며 삽입·삭제는 포함하지 않는다.

## 07. 해시 - 항목이 많아지면 크기 늘리기

[01_chaining.py](07-Hash/01_chaining.py)

항목 수가 버킷 수의 75%를 넘으면 테이블을 늘리게 했다. 새 크기는 `기존 크기 * 2 + 1`이고, 저장된 번호도 새 크기로 나눈 주소에 다시 넣는다. 같은 번호의 값만 수정할 때는 항목 수를 늘리지 않는다.

크기 5인 테이블에 2, 7, 12, 17을 넣으면 버킷이 11개가 된다. 처음에는 같은 주소에 몰렸던 번호도 새 크기로 다시 배치된다. 단, 모든 입력에서 충돌이 없어지는 것은 아니다.

균등하게 분산된다는 가정에서 삽입·검색은 평균적으로 빠르지만, 한 버킷에 몰리면 최악 O(n)이다. 확장 한 번은 O(n + m)이며 m은 새 버킷 수다. 저장 공간은 O(n + m)이다.

## 09. 분할정복 - 순서가 뒤집힌 쌍 세기

[01_merge_sort.py](09-DivideAndConquer/01_merge_sort.py)

병합 정렬을 이용해 앞의 값이 뒤의 값보다 큰 쌍을 세는 `count_inversions()`를 추가했다. 오른쪽 값이 먼저 나올 때, 왼쪽에 남은 값들은 전부 그 값보다 크므로 남은 개수를 한 번에 더한다.

`count_inversions([3, 1, 2])`는 `([1, 2, 3], 2)`를 반환한다. 뒤집힌 쌍은 `(3, 1)`, `(3, 2)` 두 개다. 같은 값끼리는 세지 않는다. 정렬 결과와 쌍의 수를 같이 반환하며, 시간 O(n log n), 최대 동시 보조 공간 O(n)이다.

각 기능은 빈 입력, 중복값, 없는 값 등을 넣어 확인했다. 범위 검색은 조건으로 전체 목록을 걸러낸 결과와, 뒤집힌 쌍의 수는 이중 반복문으로 센 결과와 비교했다.
